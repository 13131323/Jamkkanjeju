- `LoginRequestValidationTest`: 기존 이메일 검증 회귀, 공백·대문자 정규화 후 admin 허용, admin 외 이메일 아닌 아이디 거부.

- 프론트: 실제 로그인 토큰 전달, 만료·401 재로그인, 계정별 캐시 분리, 관리자 GPS 이동량 보존과 일반 사용자 좌표 유지.

### 변경 검증 결과

### 발견하고 수정한 점

- 최초 통합 테스트 시작 시 삭제된 `V4__insert_admin_user.sql`이 `target/classes`에 남아 관리자 INSERT 중복으로 초기화에 실패했다. `clean`으로 빌드 산출물을 정리한 뒤 최신 V1~V3을 적용해 27개 전부 통과했다. Flyway 검증을 끄거나 이력을 수정하지 않았다.
- 소스의 API 구현 변경 없이 계획한 검증을 통과했다.
- 동시 요청은 200·401 각 한 건, 새 토큰 기록 한 건만 생성되는 것을 확인했다.
- 저장·커밋 오류 테스트는 실제 INSERT·기존 토큰 UPDATE를 flush한 뒤 실패를 발생시켜 양쪽이 모두 롤백되는 것을 확인했다. 커밋 오류는 beforeCommit 도달 여부도 검증했다.
- 신규 통합 테스트는 실제 커밋·동시 요청 검증을 위해 테스트별 준비 데이터를 커밋하고 종료 후 정리했다. 기존 로그인 통합 테스트는 기존 트랜잭션 롤백 방식을 유지했다.
- 실패한 최초 실행을 포함해 이번 실행의 임시 DB 세 개와 접근 권한이 모두 제거된 것을 확인했다. 개발 DB·컨테이너 볼륨·프론트는 변경하지 않았다.

### 발견하고 수정한 점

- 최초 통합 실행은 공통 Blob 컨테이너 이름 설정 누락으로 컨텍스트 초기화 단계에서 실패했다. 테스트 전용 `app.blob-storage.container=logout-test`를 고정하여 외부 Blob 자격증명 없이 실행하도록 했다. 실제 Blob 서비스는 호출하지 않는다.
- 실패 주입 테스트에서 Spring Data 인터페이스의 추상 메서드를 `callRealMethod()`로 호출해 3건이 실패했다. 관리 중인 엔티티를 실제 EntityManager로 삭제·flush한 뒤 실패 또는 대기를 주입하도록 테스트 코드를 수정했다. 최종 29개 모두 통과했다.
- 삭제 후 오류와 커밋 직전 오류 모두 DB 기록이 복구되는 것을 확인했다. 동시 로그아웃은 두 요청 모두 성공하고, 로그아웃이 먼저 잠금을 획득한 경우 재발급은 거절되는 것을 확인했다.
- 토큰 오류 로그의 마스킹은 유지하면서 기존 재발급 로그 문구도 유지하도록 공통 예외 처리 로그를 요청 종류별로 구분했다. 로그아웃의 DB 처리 로직은 변경하지 않았다.
- 로그아웃 전용 테스트만 실행했다. 재발급·기존 액세스 토큰 검증 요청은 로그아웃의 연계 동작 검증에 한해 호출했다.
- 각 통합 실행의 임시 DB·권한은 종료 시 정리했다. 개발 DB·볼륨의 삭제나 Flyway 이력 수정은 하지 않았다.
