# 에이전트 저장 장소 조회 비즈니스 규칙

## 1. 인증 범위

- 에이전트 전용 경로는 사용자 JWT·개발 자동 로그인과 다른 보안 필터 체인에서 처리한다.
- 서버 환경변수 AGENT_API_TOKEN을 app.agent.token으로 읽는다. 비어 있으면 에이전트 인증을 허용하지 않되 일반 API 기동을 막지 않는다.
- 요청 헤더 X-Agent-Token 한 개의 원문을 설정값과 비교한다. 공백 제거·Bearer 접두사 처리·JWT 파싱은 하지 않는다.
- 비밀 값 비교에는 MessageDigest.isEqual을 사용한다. 토큰을 인증 객체의 credentials·객체 출력·로그·응답에 남기지 않는다.
- 일치 시 사용자 ID나 ADMIN 역할 대신 전용 AGENT_LOCATIONS_READ 권한을 부여한다.
- 현재 허용된 장소 조회 외 에이전트 경로·메서드는 기본 거부한다. 일반 API 보안 체인에는 에이전트 필터를 넣지 않는다.

## 2. 입력과 조회

- 공개 요청 조건은 API_SPEC.md를 따른다. 생략한 page·size는 각각 0·100으로 지정한다.
- 장소 ID 오름차순으로 한 페이지를 조회한다. 미션·쿠폰·방문 이력 유무나 사용자 GPS로 필터링하지 않는다.
- 다음 페이지 판단은 Slice를 사용하고 불필요한 전체 개수 집계는 하지 않는다.
- 응답 DTO에는 DB의 장소 기본 필드만 담는다. 외부 TourAPI·이미지 조회·LLM을 호출하지 않는다.
- 장소가 없거나 요청 페이지 범위를 넘으면 빈 목록으로 반환한다.

## 3. 데이터 보존과 범위

- 읽기 전용 트랜잭션으로 조회한다. 장소·미션·보상·방명록·사용자 데이터를 생성·수정·삭제하지 않는다.
- 조회 실패를 빈 결과로 바꾸지 않는다. 공통 예외 처리를 사용한다.
- 여러 페이지의 조회는 실행 전체 스냅샷을 보장하지 않는다. 이 Tool의 결과만으로 삭제를 자동 수행하지 않는다.
- 점검 예약·동기화·미션 비활성화·진행도 및 보상 상태 초기화는 이번 API 범위에 포함하지 않는다.

## 4. Python 연동

- STORED_LOCATIONS_API_URL에 이 API 주소를 설정한다. AGENT_API_TOKEN을 X-Agent-Token 헤더로 전달한다.
- 기존 SPRING_ACCESS_TOKEN 사용과 Authorization 생성은 제거한다. 자동 사용자 로그인·JWT 갱신을 추가하지 않는다.
- 토큰은 환경설정 또는 실행 프로그램에서 주입하며 모델의 Tool 입력은 page·size뿐이다.
- 로컬 양쪽 .env에 동일한 난수 토큰을 설정하고 Git에서 제외한다. 예시 파일에는 빈 값만 기록한다.
