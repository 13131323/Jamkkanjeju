# 에이전트 저장 장소 조회 비즈니스 규칙

## 1. 인증 범위

- 에이전트 전용 경로는 사용자 JWT·개발 자동 로그인과 다른 보안 필터 체인에서 처리한다.
- 서버 환경변수 AGENT_API_TOKEN을 app.agent.token으로 읽는다. 비어 있으면 에이전트 인증을 허용하지 않되 일반 API 기동을 막지 않는다.
- 요청 헤더 X-Agent-Token 한 개의 원문을 설정값과 비교한다. 공백 제거·Bearer 접두사 처리·JWT 파싱은 하지 않는다.
- 비밀 값 비교에는 MessageDigest.isEqual을 사용한다. 토큰을 인증 객체의 credentials·객체 출력·로그·응답에 남기지 않는다.
- 일치 시 사용자 ID나 ADMIN 역할 대신 전용 AGENT_LOCATIONS_READ·AGENT_MAINTENANCE_WRITE·AGENT_LOCATIONS_SYNC 권한을 부여한다.
- 장소 조회 GET·장소 방명록 조회 GET·점검 예약 POST·장소 동기화 POST만 해당 전용 권한으로 허용하고, 그 외 에이전트 경로·메서드는 기본 거부한다. 일반 API 보안 체인에는 에이전트 필터를 넣지 않는다.

## 2. 입력과 조회

- 공개 요청 조건은 API_SPEC.md를 따른다. 생략한 page·size는 각각 0·100으로 지정한다.
- 장소 ID 오름차순으로 한 페이지를 조회한다. 미션·쿠폰·방문 이력 유무나 사용자 GPS로 필터링하지 않는다.
- 다음 페이지 판단은 Slice를 사용하고 불필요한 전체 개수 집계는 하지 않는다.
- 응답 DTO에는 DB의 장소 기본 필드만 담는다. 외부 TourAPI·이미지 조회·LLM을 호출하지 않는다.
- 장소가 없거나 요청 페이지 범위를 넘으면 빈 목록으로 반환한다.

## 3. 데이터 보존과 범위

- 읽기 전용 트랜잭션으로 조회한다. 장소·미션·보상·방명록·사용자 데이터를 생성·수정·삭제하지 않는다.
- 조회 실패를 빈 결과로 바꾸지 않는다. 공통 예외 처리를 사용한다.
- 여러 페이지의 조회는 실행 전체 스냅샷을 보장하지 않는다. 이 Tool의 결과만으로 삭제를 자동 수행하지 않는다.
- 점검 예약·동기화·미션 비활성화·진행도 및 보상 상태 초기화는 이번 API 범위에 포함하지 않는다.

## 4. Python 연동

- STORED_LOCATIONS_API_URL에 이 API 주소를 설정한다. AGENT_API_TOKEN을 X-Agent-Token 헤더로 전달한다.
- 기존 SPRING_ACCESS_TOKEN 사용과 Authorization 생성은 제거한다. 자동 사용자 로그인·JWT 갱신을 추가하지 않는다.
- 토큰은 환경설정 또는 실행 프로그램에서 주입하며 모델의 Tool 입력은 page·size뿐이다.
- 로컬 양쪽 .env에 동일한 난수 토큰을 설정하고 Git에서 제외한다. 예시 파일에는 빈 값만 기록한다.

# 에이전트 점검 예약 비즈니스 규칙

## 1. 인증 및 입력

- 기존 에이전트 전용 필터 체인의 고정 토큰 검증을 재사용한다. 예약 생성 권한은 `AGENT_MAINTENANCE_WRITE`로 구분한다.
- 공지 입력의 공개 조건은 API 명세를 따른다. 요청 DTO compact constructor에서 앞뒤 공백을 제거하고 기본 문구를 적용한다.
- 정규화된 문구의 길이는 Bean Validation으로 검증한다. 입력 실패 시 저장하지 않는다.

## 2. 예약 시각과 저장

- `Clock`을 주입받아 서버 현재 시각을 한 번 읽고 Asia/Seoul 기준 `LocalDateTime`으로 변환한다.
- `MAINTENANCE`의 DATETIME 정밀도에 맞춰 나노초를 제거한다. startsAt을 받으면 그 KST 시각을 시작 시각으로 사용하고 생략·null이면 서버 현재 시각 1시간 뒤를 사용한다. 종료 예정 시각은 선택된 시작 시각 1시간 뒤로 계산한다. 자정·월말 경계도 같은 시간 덧셈으로 처리한다.
- 기존 `etc` 도메인의 `Maintenance` 엔티티와 `MaintenanceRepository`를 재사용한다.
- 문구, 계산한 일정, 예약 상태를 새 행으로 저장하고 flush 후 저장 엔티티를 응답 DTO로 변환한다.
- 쓰기 트랜잭션으로 처리하고 저장·flush 실패 시 롤백한다. 타임아웃 이후에는 클라이언트가 저장 여부를 단정하지 않는다.
- 중복 차단 정책은 이번 범위에 포함하지 않는다. 요청마다 독립된 예약을 만들며 기존 예약과 공지를 덮어쓰지 않는다.

## 3. 실행 범위

- 이 API 메서드는 예약 행 저장만 수행한다. 점검 상태 전환과 API 차단은 etc 도메인의 점검 서비스·스케줄러·필터가 수행한다. 장소 삭제·미션 진행 및 보상 초기화는 실행하지 않는다.
- 예약은 기존 홈 조회의 예약 공지 조회 조건에 포함된다.
- 사용자 JWT, 사용자 ID, ADMIN 계정이 아닌 에이전트 고정 토큰으로 호출한다. 일반 사용자 API에 대한 권한은 추가하지 않는다.
- Python의 `MAINTENANCE_API_URL`과 응답 계약을 일치시키며 인증키를 로그·응답에 남기지 않는다.

- 자연어의 날짜·오전·오후 해석은 에이전트가 담당하고 Spring은 전달받은 KST 시작 시각을 임의로 다른 날짜로 바꾸지 않는다. 요청 날짜·시간 형식 오류는 공통 요청 검증 오류를 따른다.

# 에이전트 장소 동기화 비즈니스 규칙

- 기존 고정 토큰에 장소 동기화 전용 권한을 추가하고 POST /api/v2/agent/locations/sync에만 허용한다. JWT·일반 사용자 권한으로 대체하지 않는다. 점검 예약이나 재배치는 수행하지 않는다.
- CLI 승인 후 전송된 전체 계획만 실행한다. Spring은 에이전트 메모리 스냅샷에 접근하지 않으며 snapshotId는 요청 동일성 해시에 포함되는 참조 정보이다. TourAPI 존재 확인은 에이전트 비교·실행 Tool에서 수행하며 이 API는 외부 API를 호출하지 않는다.
- requestId별 본문 해시와 완료 contentId 목록을 DB에 영속 저장한다. 내부 조정 행의 쓰기 잠금으로 동기화끼리 직렬화한다. 같은 requestId·정규화 후 같은 본문은 최초 결과를 반환하고 다른 본문은 409이다. 목록은 contentId순으로 정렬해 해시를 만든다.
- 본문의 ID와 헤더 멱등성 키가 다르면 공통 400이다. 삭제 대상 행을 잠근 뒤 locationId와 contentId를 모두 검증한다. 추가 contentId가 현재 DB에 존재하면 계획 충돌로 전체 중단한다.
- 삭제 장소와 연결된 보물·협동 미션을 활성 여부와 무관하게 잠그고 INACTIVE로 변경하며 장소 연결을 해제한다. 해당 미션의 진행도 전체 및 MISSION_REWARD_STATUS를 삭제한다. 보물 획득 항목·협동 참가자·역할 인증은 FK CASCADE로 함께 삭제된다.
- 공통 MISSION·미션 보상 설정·이미 지급한 캐릭터 조각·포인트·획득 쿠폰은 삭제하거나 회수하지 않는다. 장소 삭제의 기존 FK에 따라 방문 이력은 삭제되고 장소 방명록의 방문 참조 및 쿠폰 장소는 null이 되며 방명록 자체는 남는다. 문화 미션은 처리 대상이 아니다.
- 새 장소는 새 PK로 추가한다. 기존 장소를 덮어쓰지 않으며 승인하지 않은 장소·미션을 추가 변경하지 않는다.
- 실행 기록·미션 상태 변경·진행도/보상 상태 정리·장소 추가/삭제를 하나의 쓰기 트랜잭션으로 처리한다. 실패하면 전부 롤백한다. 완료 기록도 같은 커밋에서 저장한다.
- 동기화 테이블 내부 조정 행은 외부 requestId 형식과 구분되며 삭제하거나 API 결과로 반환하지 않는다. 정기 스케줄이나 자동 동기화 작업은 추가하지 않는다.


# 장소 방명록 감성 분석용 조회
- 장소 방명록 → 방문 기록 → 장소가 모두 연결되고 공통 방명록 상태가 ACTIVE인 행을 조회한다. 길바닥 방명록과 장소가 분리된 행은 제외한다.
- 텍스트가 없는 사진·소리 등의 방명록도 제외하지 않는다. ID 오름차순 Slice이며 읽기 전용이다.
- 고정 토큰에 AGENT_LOCATIONS_READ 권한이 있을 때만 GET /api/v2/agent/guestbooks를 허용한다.
- Python은 전체 장소와 전체 방명록 페이지 조회 성공 후 로컬 감성 모델로 개별 방명록을 분석한다. null·공백은 미확인이고 나머지는 긍정/부정이다.
- 장소명·ID, 긍정/부정/미확인 ID 배열과 건수, 부정/전체 비율을 메모리 스냅샷에 저장한다. 원문·점수·개별 sentiment 필드는 저장하지 않는다.
- 방명록 없는 장소도 포함하며 비율은 null이다. 조회·분석 실패 시 부분 스냅샷은 생성하지 않는다. 보고서 Tool은 후속 작업이다.

## 방명록 ID별 원문 조회
- guestbookIds를 지정하면 같은 ACTIVE·장소 연결 조건에 ID 조건을 추가한 뒤 페이지 조회한다. 생략하면 기존 전체 조회를 유지한다.
- 존재하지 않거나 비활성화·장소 연결이 해제된 ID는 빈 결과 또는 일부 결과로 반환한다. DB나 감성 분석 결과를 변경하지 않는다.
- Python 원문 Tool은 요청 ID를 최대 100개씩 나누어 읽는다. 일부 요청 실패를 누락 ID로 바꾸거나 부분 성공으로 반환하지 않는다.
