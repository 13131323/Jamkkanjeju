# 홈 조회 비즈니스 규칙

## 1. 요청 및 현재 사용자 확인

- 요청 위치와 응답 형식은 [API 명세](./API_SPEC.md)를 따른다.
- 요청 위도는 -90 이상 90 이하, 경도는 -180 이상 180 이하만 허용하며, 범위를 벗어나면 `INVALID_REQUEST`로 처리한다.
- 현재 사용자 ID는 검증된 인증 정보에서 가져온다.
- 요청에서 사용자 ID를 받지 않는다.
- 인증 정보에 해당하는 사용자를 조회한다.
- 사용자가 존재하지 않으면 `UNAUTHORIZED`로 처리하고 홈 데이터를 조회하지 않는다.
- 홈 조회는 추천 미션, 진행 중인 미션, 서비스에 쌓인 방명록 개수, 온보딩 결과의 프로필 이미지를 구성한다.

## 2. 미션 공통 정보

- 미션은 `MISSION.id`를 기준으로 식별한다.
- 유형별 세부 미션의 `mission_id`는 공통 미션 ID와 동일하다.
- 추천 미션과 진행 중인 미션의 `missionId`에는 공통 미션 ID를 사용한다.
- 미션 유형과 이름은 `MISSION.mission_type_id`로 연결된 `MISSION_TYPE.type`, `MISSION_TYPE.title`을 사용한다.
- 문화 미션은 장소가 없는 미션으로 처리한다.
- 협동 미션과 보물찾기 미션의 장소는 각 세부 미션의 `location_id`로 연결된 `LOCATION`을 사용한다.

## 3. 추천 미션 선정

- 추천 미션 선정 로직은 홈 서비스의 데이터 조합 로직과 분리한 별도 컴포넌트로 구현한다.
- 문화, 협동, 보물찾기 미션을 유형별로 한 건씩 선정한다.
- 추천 후보는 세부 미션의 `status`가 `ACTIVE`인 미션으로 한정한다.
- 문화 미션은 장소가 없으므로 문화 미션 중 무작위로 한 건을 선택한다.
- 협동 미션과 보물찾기 미션은 현재 사용자가 완료한 이력이 없는 미션 중 요청 위치에서 가장 가까운 장소의 미션을 한 건 선택한다.
- 장소 좌표가 없는 협동 미션과 보물찾기 미션은 거리 비교 대상에서 제외한다.
- 보물찾기 완료 여부는 현재 사용자의 해당 `TREASURE_MISSION_PROGRESS.mission_status`가 `COMPLETED`인지로 판단한다.
- 협동 완료 여부는 현재 사용자의 `COOPERATIVE_MISSION_PARTICIPANT.participant_status`가 `ACCEPTED`이고, 연결된 `COOPERATIVE_MISSION_PROGRESS.mission_status`가 `COMPLETED`인 기록이 존재하는지로 판단한다.
- 현재 스키마에는 협동 참가자와 진행도의 삭제 여부 컬럼이 없으므로, 기존 FastAPI의 삭제 플래그 조건을 적용하지 않고 현재 존재하는 기록을 기준으로 판단한다.
- 미션 완료 여부 판정은 다른 조회 기능에서도 같은 기준을 사용할 수 있도록 공통 로직으로 분리한다.
- 선정할 후보가 없는 유형은 추천 목록에서 제외한다.
- 추천 목록은 최대 세 건이며 모든 유형에 후보가 없으면 빈 목록으로 구성한다.

## 4. 거리 및 예상 소요 시간 계산

- 요청한 위도와 경도를 거리 계산의 기준 위치로 사용한다.
- 미션 장소가 있으면 요청 위치와 장소 좌표 사이의 직선거리를 계산한다.
- 예상 소요 시간은 직선거리 100m를 1분 20초에 걷는 기존 기준을 사용한다.
- 분 단위 예상 소요 시간은 거리(m)에 `80 / 100 / 60`을 곱해 계산한다.
- 거리와 예상 소요 시간은 각각 계산한 값을 정수로 반올림해 응답한다.
- 추천 미션과 진행 중인 미션에 같은 거리·시간 계산 기준을 적용한다.
- 실제 도로 경로와 교통수단에 따른 이동 시간은 계산하지 않는다.
- 거리 및 예상 소요 시간 계산은 추후 변경할 수 있도록 별도 공통 컴포넌트로 분리한다.
- 거리 계산 코드에 `// TODO: 추후 확정된 거리 계산 방식으로 현재 직선거리 계산 로직을 교체한다.` 주석을 남긴다.
- 예상 소요 시간 계산 코드에 `// TODO: 추후 확정된 소요 시간 계산 방식으로 현재 직선거리 기반 도보 시간 추정 로직을 교체한다.` 주석을 남긴다.
- 장소가 없는 미션은 장소명, 장소 좌표, 거리, 예상 소요 시간을 `null`로 구성한다.
- 응답에 포함하는 항목은 [API 명세](./API_SPEC.md)를 따른다.

## 5. 진행 중인 미션 조회

- 미션 유형별 진행도에서 `mission_status`가 `IN_PROGRESS`인 데이터를 조회한다.
- 문화 미션은 `CULTURE_MISSION_PROGRESS.user_id`로 현재 사용자의 진행도를 조회한다.
- 보물찾기 미션은 `TREASURE_MISSION_PROGRESS.user_id`로 현재 사용자의 진행도를 조회한다.
- 협동 미션은 현재 사용자의 참가자 기록에서 `cooperative_mission_progress_id`로 연결된 팀 진행도를 조회한다.
- 협동 미션의 역할별 진행 기록을 함께 조회하더라도 같은 팀 진행도가 역할 개수만큼 중복되지 않도록 한다.
- 협동 미션의 현재 단계와 전체 진행 상태는 개인 역할 진행도가 아닌 팀 진행도를 기준으로 한다.
- 완료된 진행도는 진행 중인 미션 목록에서 제외한다.
- 진행 중인 미션이 없으면 빈 목록으로 구성한다.

## 6. 단계 정보 구성

- 단계 정보는 프론트가 진행 상태를 표시하는 데 필요한 값을 제공한다.
- 문화 미션의 `totalStep`은 해당 미션에 연결된 `CULTURE_MISSION_QUIZ`의 개수로 구성한다.
- 문화 미션의 `currentStep`은 `CULTURE_MISSION_PROGRESS.current_quiz_index`를 사용한다.
- 협동 미션의 `totalStep`은 연결된 `MISSION_TYPE.steps`의 항목 개수로 구성한다.
- 협동 미션의 `currentStep`은 `COOPERATIVE_MISSION_PROGRESS.current_step`을 사용한다.
- 보물찾기 미션의 `totalStep`은 전체 보물 개수인 `TREASURE_MISSION.item_total_count`를 사용한다.
- 보물찾기 미션의 `currentStep`은 현재 찾은 보물 개수인 `TREASURE_MISSION_PROGRESS.found_item_count`를 사용한다.
- 홈 조회에서 프론트의 화면 전환 정책을 추가로 판단하지 않는다.

## 7. 방명록 개수 집계

- 방명록 집계 로직은 홈 서비스의 데이터 조합 로직과 분리한 별도 컴포넌트로 구현한다.
- 현재 사용자가 작성한 방명록 수가 아닌 서비스 전체의 방명록 수를 집계한다.
- 일반 방명록과 길바닥 방명록을 모두 포함하며, 생성 시각(`created_at`)이 현재 사용자의 `guestbook_last_checked_at`보다 늦고 서버 현재 시각 이하인 기록만 집계한다.
- 서버 현재 시각은 주입받은 `Clock`을 Asia/Seoul 기준으로 변환하여 한 번 구한다. 홈 조회에서는 마지막 확인 시각을 갱신하지 않는다.
- 현재 구조에서는 공통 `GUESTBOOK`을 기준으로 집계한다.
- `LOCATION_GUESTBOOK`과 `ROAD_GUESTBOOK`은 공통 방명록의 세부 정보이므로, 공통 행과 세부 행을 각각 더해 중복 집계하지 않는다.
- 집계 대상이 없으면 개수는 0으로 구성한다.
- 마지막 확인 시각과 같은 시각의 기록 및 서버 현재 시각보다 미래인 기록은 집계하지 않는다. 방명록 조회 API가 정상 처리될 때 마지막 확인 시각이 갱신된다.

## 8. 온보딩 캐릭터 이미지 구성

- 사용자의 `onboarding_result_id`로 연결된 `ONBOARDING_RESULT.profile_img_url`을 `characterImgUrl`로 구성한다.
- 온보딩 완료 응답의 `profileImageUrl`과 같은 이미지를 사용한다.
- 나중에 하기를 선택한 사용자도 배정된 기본 온보딩 결과의 이미지를 사용한다.
- 온보딩 결과가 없는 사용자는 이미지 값을 `null`로 구성한다.
- 보유 AR 캐릭터에서 대표 이미지를 선택하거나 새 AR 캐릭터를 배정하지 않는다.

## 9. 조회 처리 및 재요청

- 홈 조회는 읽기 전용으로 처리한다.
- 사용자, 미션 진행도, 방명록, 온보딩 결과를 생성하거나 변경하지 않는다.
- 재요청할 때마다 현재 데이터와 요청 위치를 기준으로 홈 정보를 다시 구성한다.
- 문화 미션은 무작위 추천이므로 같은 위치로 재요청해도 추천 결과가 달라질 수 있다.
- 홈 정보 구성 중 예기치 않은 오류가 발생하면 처리를 실패시키며, 오류 응답은 [API 명세](./API_SPEC.md)를 따른다.
