# 미션 홈 조회 비즈니스 규칙

## 1. 요청 및 현재 사용자 확인

- 요청과 응답 형식은 [API 명세](./API_SPEC.md)를 따른다.
- 현재 사용자 ID는 검증된 인증 정보에서 가져오며 요청에서 별도로 받지 않는다.
- 인증 정보에 해당하는 사용자가 존재하는지 확인한다.
- 사용자가 존재하지 않으면 공통 인증 오류로 처리하고 미션 홈 정보를 조회하지 않는다.

## 2. 미션 식별 및 활성 상태 확인

- 요청의 `missionId`는 공통 `MISSION.id`이며 진행도 ID가 아니다.
- 공통 미션에 연결된 `MISSION_TYPE.type`으로 미션 유형을 확인한다. 요청에서 유형을 별도로 받지 않는다.
- 확인한 유형의 세부 미션을 공통 미션과 동일한 `mission_id`로 조회한다.
- 공통 미션 또는 해당 유형의 세부 미션이 존재하지 않으면 `MISSION_NOT_FOUND`로 처리한다.
- 다른 유형의 세부 미션을 대신 반환하지 않는다.
- 세부 미션의 `status`가 `INACTIVE`이면 `MISSION_INACTIVE`로 처리한다.
- 활성 상태 검증은 문화·협동·보물찾기 미션에 동일하게 적용한다.

## 3. 미션 공통 정보 구성

- 응답의 `id`는 공통 `MISSION.id`를 사용한다.
- 미션 유형, 제목과 설명은 연결된 `MISSION_TYPE`의 `type`, `title`, `description`을 사용한다.
- 단계 목록은 `MISSION_TYPE.steps`를 사용하고 `step` 오름차순으로 정렬한다.
- 단계 제목은 저장된 `step_title`을 응답의 `stepTitle`로 구성한다.
- 단계 목록은 미션 안내 정보이며, 사용자의 현재 진행 단계나 문화 미션 문제 목록으로 대체하지 않는다.

## 4. 보상 설정 및 사용자별 지급 상태 확인

- 전체 보상 설정은 조회한 유형별 세부 미션의 `ar_character_id`, `point`, `coupon_id`를 사용한다.
- 현재 사용자와 해당 공통 미션의 `(mission_id, user_id)`로 `MISSION_REWARD_STATUS`를 조회한다.
- 지급 상태 기록이 없으면 모든 보상 항목이 아직 지급되지 않은 것으로 판단한다.
- 지급 상태가 있으면 항목별 지급 여부를 독립적으로 확인한다.
- 남은 보상 판단에 진행도 이력을 조회하거나 현재 진행 상태·완료 여부를 사용하지 않는다.
- 다른 사용자나 다른 미션의 지급 상태를 현재 미션의 보상 판단에 사용하지 않는다.
- 미션 재도전 여부와 무관하게 누적된 지급 상태를 기준으로 판단한다.

## 5. 남은 보상 구성

- `ar_character_id`가 있고 `ar_character_reward_granted`가 미지급이면 연결된 캐릭터의 ID·이름·이미지 URL을 반환한다.
- 캐릭터 보상이 설정되어 있지 않거나 이미 지급됐다면 해당 항목은 `null`로 구성한다.
- `point`가 `null`이 아니고 `point_reward_granted`가 미지급이면 설정된 포인트 값을 반환한다.
- 포인트 보상이 설정되어 있지 않거나 이미 지급됐다면 해당 항목은 `null`로 구성한다.
- `coupon_id`가 있고 `coupon_reward_granted`가 미지급이면 연결된 쿠폰의 사용처와 금액을 반환한다.
- 쿠폰 보상이 설정되어 있지 않거나 이미 지급됐다면 해당 항목은 `null`로 구성한다.
- 쿠폰은 있으나 연결된 장소가 없으면 쿠폰 객체는 유지하고 사용처만 `null`로 구성한다.
- 모든 보상이 지급됐거나 설정된 보상이 없어도 `remainingReward` 객체는 유지하고 각 항목을 `null`로 구성한다.
- 이 API는 지급 가능한 남은 보상을 안내하며, 정답 수에 따른 지급 개수 계산이나 실제 보상 지급은 수행하지 않는다.

## 6. 조회 전용 처리 및 예외

- 전체 조회와 응답 구성은 읽기 전용 트랜잭션에서 처리한다.
- 지급 상태 기록이 없더라도 새 기록을 생성하지 않는다.
- 조회 요청으로 진행도, 보상 지급 여부, 사용자 포인트 및 획득 기록을 생성·변경·삭제하지 않는다.
- 반복 조회는 그 시점에 저장된 미션 정보와 사용자별 보상 지급 상태를 기준으로 응답한다.
- 예상하지 못한 DB 오류나 응답 구성 실패는 미션 없음으로 바꾸지 않고 공통 서버 오류로 처리한다.
