# 이메일·비밀번호 입력 규칙

회원가입, 로그인, 비밀번호 변경 등 이메일과 비밀번호를 입력받는 기능에서 공통으로 적용한다. 프론트엔드와 백엔드에서 동일하게 검증하되, 최종 검증 책임은 백엔드에 있다.

## 1. 이메일 규칙

| 항목 | 규칙 |
| --- | --- |
| 필수 여부 | 필수 |
| 최대 길이 | 255자 |
| 형식 | 일반적인 이메일 형식인 `local-part@domain` |
| 공백 | 앞뒤 공백은 제거하며, 이메일 내부 공백은 허용하지 않음 |
| 대소문자 | 앞뒤 공백을 제거한 뒤 전체를 소문자로 변환 |
| 저장 및 조회 | 소문자로 정규화한 이메일을 저장하고 조회에 사용 |
| 중복 | 정규화한 이메일을 기준으로 중복을 허용하지 않음 |

- 빈 문자열과 공백만 있는 값은 허용하지 않는다.
- `@` 앞뒤 값이 모두 존재해야 하며 도메인 형식이 올바르지 않은 값은 허용하지 않는다.
- 로그인 요청에서도 동일한 정규화 과정을 거친 뒤 사용자를 조회한다.
- 이메일 원문이 필요하지 않으므로 정규화 전 값은 별도로 저장하지 않는다.

### 예시

| 입력값 | 처리 결과 |
| --- | --- |
| `User@Example.com` | `user@example.com`으로 정규화 |
| `  user@example.com  ` | `user@example.com`으로 정규화 |
| `user example.com` | 이메일 형식 오류 |
| `user@example` | 이메일 형식 오류 |

## 2. 비밀번호 규칙

| 항목 | 규칙 |
| --- | --- |
| 필수 여부 | 필수 |
| 길이 | 8자 이상 64자 이하 |
| 허용 문자 | 영문 대문자·소문자, 숫자, ASCII 특수문자 |
| 금지 문자 | 한글, 이모지, 그 밖의 비ASCII 문자 |
| 공백 | 스페이스, 탭, 줄바꿈을 포함한 모든 공백 문자 금지 |
| 대소문자 | 구분함 |
| 정규화 | 공백 제거, 소문자 변환 등 어떠한 변형도 적용하지 않음 |

- 허용되는 문자는 ASCII의 출력 가능한 문자 중 공백을 제외한 `!`부터 `~`까지다.
- 영문, 숫자, 특수문자는 사용할 수 있지만 각 문자 종류를 반드시 하나 이상 포함해야 하는 것은 아니다.
- 길이는 사용자가 입력한 비밀번호 원문을 기준으로 검사한다.
- 서버는 비밀번호 원문을 저장하거나 로그에 기록하지 않는다.
- 비밀번호는 BCrypt로 해시한 값만 `USER.password_hash`에 저장한다.
- 로그인 시 요청 비밀번호를 변경하지 않고 저장된 BCrypt 해시와 비교한다.

### 예시

| 입력값 | 결과 | 사유 |
| --- | --- | --- |
| `password123!` | 허용 | 8~64자의 허용 문자로 구성 |
| `Abcd1234` | 허용 | 영문과 숫자로 구성 |
| `12345678` | 허용 | 숫자만 사용해도 허용 |
| `pass word1!` | 거부 | 공백 포함 |
| `비밀번호123!` | 거부 | 한글 포함 |
| `password😀` | 거부 | 이모지 포함 |
| `abc1!` | 거부 | 8자 미만 |

## 3. 검증 적용 순서

1. 필수값 여부를 검사한다.
2. 이메일은 앞뒤 공백을 제거하고 소문자로 변환한다.
3. 이메일 형식과 최대 길이를 검사한다.
4. 비밀번호는 원문을 변경하지 않고 길이와 허용 문자 범위를 검사한다.
5. 입력 규칙을 통과한 값만 인증 또는 저장 처리에 사용한다.
