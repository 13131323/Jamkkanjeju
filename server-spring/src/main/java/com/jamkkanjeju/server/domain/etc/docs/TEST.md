- 상태: 완료
- 실행일: 2026-11-17
- 결과: 단위·인증 26개, 임시 MySQL 통합 11개, 총 37개 통과. 실패·오류·건너뜀 0개. 전체 테스트는 실행하지 않았다.
- 기준: API_SPEC.md, BUISNESS_RULE.md
- 범위: 이번 점검 상태 전환·필터 및 기존 에이전트 인증 필터만 검증한다. 전체 테스트는 실행하지 않는다.

## 진행 방식

| 구분 | 방법 |
| --- | --- |
| 단위 | MaintenanceAccessFilterTest: MockHttpServletRequest·고정 점검 상태·실제 공통 JSON writer로 차단·허용·프리플라이트·조회 실패를 검증 |
| 통합 | MaintenanceIntegrationTest: 실행별 임시 Docker MySQL, 고정 Clock, 테스트별 롤백으로 상태 전환 쿼리·재시작 복구·반복·중첩 예약과 실제 SecurityFilterChain 예외를 검증 |
| 회귀 | 기존 AgentTokenAuthenticationFilterTest로 사용자 JWT와 분리된 고정 토큰 인증을 재확인 |

## 검증 항목

- 차단: 일반 GET·POST·PATCH·DELETE 및 로그아웃, 허용 경로의 다른 메서드는 503이며 컨트롤러를 호출하지 않는다.
- 허용: 홈 GET·로그인 POST·재발급 POST는 정상 체인으로 진행하며 인증·입력 검증은 유지한다. 에이전트 API는 고정 토큰 검증을 유지한다.
- 점검 전후: 예약 중은 정상 처리하고 시작 시각은 진행 중, 종료 예정 시각부터 완료·차단 해제한다.
- 재시작: 이미 끝난 예약은 완료 처리하고 현재 유효 예약만 시작한다. 실패·취소·완료는 보존한다.
- 반복·중첩: 반복 실행은 새 행을 만들지 않으며 겹친 유효 예약이 있으면 계속 차단한다.
- 오류·비대상: OPTIONS·문서·헬스 체크는 점검 DB를 조회하지 않으며 상태 조회 실패 시 공통 500으로 종료한다.
- 실제 DB·인증: KST 기준 시각과 저장 상태를 확인하고 홈은 토큰 없이 401, 로그인·재발급 잘못된 입력은 400, 고정 토큰 장소 조회는 200인지 검증한다.

## 발견하고 수정한 점

- 시작·종료 정확한 시각, 재시작 중 지난 예약, 중첩 예약, 반복 실행의 조건부 UPDATE를 실제 MySQL에서 확인했다.
- 인증된 홈 조회의 maintenance.status가 IN_PROGRESS임을 확인했고 비인증 홈 요청은 기존 401, 잘못된 로그인·재발급 입력은 400이었다.
- 일반 API와 허용 경로의 잘못된 메서드는 503, 정상 고정 토큰의 에이전트 조회는 200, 토큰 없는 에이전트 조회는 401이었다.
- 추가 테스트의 토큰 접근자를 기존 IssuedToken.value()에 맞춘 뒤 통합 테스트를 재실행해 통과했다.
- 임시 DB tour_test_52f4557b5ffb407f87b81b9ce06a559f는 실행 종료 시 자동 삭제됐다. 개발 DB·기존 실행 컨테이너·볼륨은 변경하지 않았다.
