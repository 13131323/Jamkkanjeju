- 대상: `GET /api/v2/users/me/mypage`
- 기준: `API_SPEC.md`, `BUISNESS_RULE.md`

## 진행 방식

- 단위 테스트는 JUnit 5·AssertJ·Mockito로 사용자 부재·빈 결과·응답 변환을 검증한다.
- HTTP 통합 테스트는 `MySqlIntegrationTestSupport`의 실행별 임시 MySQL과 실제 JWT·MockMvc를 사용한다. 준비 데이터는 각 테스트 트랜잭션으로 롤백한다.

## 단위 테스트 계획

| 테스트 클래스 | 검증 내용 |
| --- | --- |
| `MyPageServiceTest` | 사용자 부재의 공통 인증 오류·후속 조회 중단, 빈 도감에서 조각·보상 후보 조회 생략, 저장된 목표·포인트와 nullable 프로필 유지 |
| `GetMyPageResponseTest` | 온보딩 프로필 변환, 응답 목록 복사·이전 필드 제외 |

## 통합 테스트 계획

| 테스트 클래스 | 검증 내용 |
| --- | --- |
| `GetMyPageApiIntegrationTest` | 실제 JWT와 200 JSON·공통 401, 초기 사용자 데이터와 조회 전후 상태 유지, 미완성·완성·초과 조각 및 10 초과 필요 조각 수, 최초 완성 날짜, 미션 후보 제외 후 최대 3·2·1·0개, 완료·기지급·비활성·타 사용자 격리, 협동 ACCEPTED와 PENDING 및 팀별 완료 집계, 공통 미션 ID·유형별 진행 수, 빈 도감·프로필 null, Swagger |

## 실행 순서와 완료 조건

1. 단위 테스트를 먼저 실행한다.
2. 실제 HTTP·JPA·집계 조합을 임시 DB에서 검증한다.
3. 관련 홈·미션 홈 조회 테스트를 회귀 확인한다.
4. 실패가 없고 실행 후 임시 DB·접근 권한이 제거되면 실제 결과를 기록한다. 개발 DB·볼륨은 변경하지 않는다.

## 결과

- 2026-10-30: 마이페이지 단위 4개·HTTP 통합 9개, 총 13개 통과. 실패·오류·건너뜀 0개.
- 기존 `GetMissionHomeApiIntegrationTest` 19개도 통과했다. 전체 테스트는 반복 실행하지 않았다.
- 현재 조각 6·8·9·10개에 대한 후보 3·2·1·0개, 12개 초과 집계·열 번째 조각 날짜, 필요 조각 수 15개 설정, ACCEPTED/PENDING·팀별 집계, 프로필·이전 필드 제거·읽기 전후 사용자 상태 유지·Swagger를 실제 HTTP로 확인했다.
- 최초 통합 실행에서 테스트가 JDBC로 필요 조각 수를 바꾼 뒤 기존 영속성 컨텍스트를 재사용하여 설정 변경 검증 한 건이 실패했다. 준비 데이터 변경 후 컨텍스트를 비우도록 수정했고 최종 통합 9개가 모두 통과했다.
- 최종 임시 DB `tour_test_e4773a7d09fc4ea0b0d7f0e143b7135c`의 자동 제거 로그를 확인했다. 개발 DB·볼륨·스키마·보상 지급 상태는 변경하지 않았다.

2. 임시 MySQL에서 신규 API HTTP 통합 테스트를 실행한다.
3. 온보딩·마이페이지·다른 공유 저장소 사용처를 포함한 전체 백엔드 테스트를 한 번 실행한다.
4. 전체 결과와 임시 DB 자동 정리를 확인하고 실행 결과를 기록한다.

- 개발 DB·볼륨을 변경하지 않고 실행별 임시 DB와 권한이 정리되어야 한다.

## 발견하고 수정한 점

- FastAPI에서 복사한 프롬프트의 Windows CRLF를 원문 LF로 맞추고 `.gitattributes`로 해당 리소스의 LF를 고정했다. 문구는 바꾸지 않았으며 FastAPI 상수와 바이트까지 일치함을 확인했다.
- 프롬프트 본문에도 manifest 태그를 설명하는 문구가 있어 테스트의 JSON 추출 위치를 실제 마지막 manifest 블록으로 수정했다.
- JDBC 날짜 반환 타입을 고정 Timestamp로 가정하지 않고 LocalDateTime 변환 조회로 검증하도록 수정했다. 예외를 던지도록 만든 모의 객체는 doReturn으로 재설정했다.
- Spring Data 인터페이스 spy에서 추상 메서드의 callRealMethod를 호출하는 테스트 오류를 수정했다. 커밋 실패 케이스는 실제 JPA persist·flush 후 beforeCommit에서 실패시키고, 그 지점 도달 여부·DB 차감/행 롤백·정확한 Blob 삭제 이름을 확인한다.
- 비즈니스 서비스의 로직 수정은 없었다. 새 테스트 외에 수정한 파일은 프롬프트 줄바꿈과 이를 보존하는 Git 속성이다.
