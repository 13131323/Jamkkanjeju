# 미션 홈 조회 API 테스트 계획

- 상태: **완료**
- 실행일: 2026-10-15
- 전체 결과: 미션 홈 단위 23개·통합 19개 및 기존 테스트 287개, 총 329개 통과. 실패·오류·건너뜀 0개.
- 대상 API: `GET /api/v2/missions/{missionId}`
- 기준 문서: `API_SPEC.md`, `BUISNESS_RULE.md`, `common/docs/commonError.md`

## 진행 방식

| 구분 | 방법 |
| --- | --- |
| 단위 테스트 | Spring·DB 없이 JUnit 5·AssertJ·Mockito로 응답 변환과 서비스 분기를 검증한다. 공통 픽스처는 `mission/support`에 둔다. |
| 통합 테스트 | 실제 Docker MySQL의 임시 테스트 DB, `@SpringBootTest`·MockMvc·실제 JWT로 HTTP부터 JPA 조회와 데이터 유지까지 확인한다. 개발용 자동 인증은 끈다. |

기존 DB에는 통합 전 보상 테이블이 있으므로 임시 DB에 Flyway V1~V3를 적용한다. 테스트 준비 데이터는 트랜잭션 종료 시 롤백하고, 전체 실행 후 임시 DB와 임시 DB 접근 권한을 제거한다. 기존 DB·컨테이너·볼륨은 변경하지 않는다. 이 API는 조회 전용이므로 쓰기 API의 롤백 대신 정상·오류·반복 요청에서 저장 상태가 유지되는지를 검증한다.

| 서버 오류 | 보상 조회 실패를 유도해 공통 500과 내부 메시지 비노출, 준비 데이터 유지 확인 |

## 실행 순서

1. DTO·서비스 단위 테스트를 작성하고 실행한다.
2. 임시 MySQL DB에서 통합 테스트를 작성하고 실행한다.
3. 같은 임시 DB에서 기존 전체 테스트를 실행해 회귀 오류를 확인한다.
4. 임시 DB와 권한을 정리하고 실제 결과를 기록한다.

## 완료 조건

- 계획한 단위·통합 테스트와 기존 테스트가 통과한다.
- 세 유형 조회, 미지급 보상, 격리, 인증·도메인 오류와 조회 전용 동작이 검증된다.
- 기존 사용자 ID·외부 API·무작위 보상 선택에 의존하지 않는다.
- 기존 DB 데이터는 유지되고 임시 DB가 남지 않는다.

## 발견하고 수정한 점

- 운영 코드 수정 없이 전체 테스트가 통과했다. 새 테스트 42개를 추가했다.
- 세 유형의 정상·상세 없음·비활성·nullable 보상은 매개변수화 테스트로 검증했다. 지급 여부 8가지 조합은 단위 테스트에서, 사용자·미션별 독립성과 실제 데이터 유지는 통합 테스트에서 검증했다.
- 잘못된 Path와 토큰 오류는 한 테스트에서 여러 요청을 보내 각각 code·message와 데이터 유지를 확인했다. 별도 관리자 권한 조건이 없는 API이므로 이 API에 임의의 403 정책을 추가하지 않았다.
- JWT 발급·검증 시각은 고정 Clock으로 제어했다. 안내 제목·설명·단계를 테스트에서 고정하고, 준비 데이터의 키만 중복 방지용으로 생성했다.
- 조회 전후 DB 스냅샷을 비교해 정상·반복·거절·500 요청에서 포인트, 획득 기록, 진행도와 지급 여부가 유지됨을 확인했다. 지급 상태가 없는 요청에서도 상태 행이 생성되지 않았다.
- 임시 DB `tour_mission_test_20261015_1615`에서 최신 Flyway V1~V3 적용과 Hibernate 스키마 검증, 전체 회귀 테스트를 수행했다. 기존 `tour` DB에 테스트 데이터를 넣거나 볼륨·컨테이너를 재생성하지 않았다.
- 실행 후 임시 DB와 해당 DB에만 부여했던 접근 권한을 제거했고, 둘 다 남은 개수가 0임을 확인했다. 제거한 데이터는 테스트용 데이터뿐이다.
