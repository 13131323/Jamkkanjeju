# 쿠폰 사용 처리 API 비즈니스 규칙

## 1. 처리 순서

1. 인증 정보에서 현재 사용자 ID를 읽는다. 클라이언트로부터 사용자 ID나 사용 시각을 받지 않는다.
2. 요청한 쿠폰이 존재하는지 확인한다. 없으면 COUPON_NOT_FOUND로 처리한다.
3. couponId와 현재 사용자 ID로 ACQUIRED_COUPON의 복합키를 구성하고 획득 기록을 조회한다. 없으면 ACQUIRED_COUPON_NOT_FOUND로 처리한다.
4. used_at이 이미 저장돼 있으면 COUPON_ALREADY_USED로 처리한다. 기존 사용 시각은 변경하지 않는다.
5. 주입받은 Clock의 현재 시각을 used_at에 저장한다.
6. 정상 종료하며 응답 본문을 반환하지 않는다.

## 2. 사용 처리와 데이터 유지

- 사용 처리 대상은 현재 사용자의 획득 기록 한 건이다. 같은 쿠폰을 다른 사용자가 보유한 기록은 변경하지 않는다.
- 획득 기록과 쿠폰 정의를 삭제하지 않으며, acquired_at·쿠폰 금액·보상 지급 기록을 변경하지 않는다.
- 재요청에서 사용 시각을 덮어쓰거나 성공으로 처리하지 않는다.
- 쿠폰 사용 여부의 기준은 ACQUIRED_COUPON.used_at이다. 클라이언트 localStorage의 사용 상태는 사용하지 않는다.
- 지도 홈은 사용 완료한 획득 쿠폰도 반환하며 사용 시각을 usedAt으로 제공한다.

## 3. 트랜잭션과 동시 요청

- 획득 기록 조회·사용 여부 확인·사용 시각 저장을 하나의 쓰기 트랜잭션에서 처리한다.
- 조회할 획득 기록에 비관적 쓰기 잠금을 적용한다. 같은 사용자·쿠폰의 동시 요청은 순서대로 확인하여 최초 요청만 성공하고 후속 요청은 이미 사용한 쿠폰으로 처리한다.
- 오류가 발생하면 사용 시각 변경을 롤백하며 기존 데이터는 유지한다.
