# GuestbookFeedScreen 변환 메모

원본: `localfiles/00penpot/travelnote.html` (Penpot 보드 `TravelNote` > `GuestbookScreen`)

## 0. 파일명 선정 근거

원본 파일명은 `travelnote.html`이지만, 실제 보드/화면 이름은 `GuestbookScreen`이었고 화면 내용도 "방명록" 타이틀 + "여행자들이 남긴 흔적을 발견하세요" 부제 + 필터/탭/정렬 + 방명록 카드 피드로 구성된 **여행지 방명록(길보드) 발견 피드 화면**이었다. 원본 파일명을 음역하지 않고 화면 내용을 그대로 드러내는 `GuestbookFeedScreen`으로 명명.

## 1. 여러 보드/중복 판단 근거 (중요)

HTML 안에 동일한 `GuestbookScreen` 콘텐츠(동일한 텍스트 10개 카드, 동일한 헤더/필터/탭)가 **총 3회 연속 반복**되어 있었다(`<!-- frame: GuestbookScreen -->` 3회, 각각의 텍스트 노드를 diff한 결과 완전히 동일). 첫 번째 등장(파일 3898번째 줄~)만 변환 대상으로 삼고 2번째·3번째는 완전한 중복 export로 판단해 무시했다. 또한 `GuestbookScreen` 프레임 바로 바깥의 `<!-- rect: Rectangle 1 -->` (이미지 썸네일, `container-a0accfaf6b44` 레벨)는 실제 화면(`GuestbookScreen` 360x800/801 프레임) 밖에 위치한 캔버스 잔재로 판단해 변환에서 제외했다.

또한 카테고리 탭 중 `📮 AI 엽서` 탭(`.button-4c3ce2d3137a`)은 원본 CSS에 `display: none`이 명시돼 있어 렌더링에서 제외했다(가이드 2번 규칙 "화면에 실제로 보여야 할 것만 반영"). 최종 탭: 전체 / 🎨 컬러 / 🎵 음악 / 🌤 날씨 / 📷 사진.

## 2. 카드 피드 레이아웃 판단 (가장 큰 임의 판단)

원본은 방명록 카드 10개를 **`transform: matrix(...)`로 살짝 회전시켜 압정으로 꽂은 듯한 콜크보드(cork-board) 콜라주** 형태로, `width: 760px`짜리 가상 캔버스(`container-eeab8b0cca80`, 실제 프레임의 2배 이상 폭) 위에 절대좌표로 흩뿌려 놓았다. 이 캔버스는 `overflow: hidden`인 360×553.93px 부모(`container-9af8677b61ff`) 안에 `left: -10px`로 배치되어 있어서, **좌표를 그대로 계산해 보면 카드 10개 중 3개(`성산일출봉 새벽 컬러` 색상 카드, `섭지코지 · 맑음` 날씨 카드, `AI 엽서 · 광치기해변` 엽서 카드)는 실제로는 보이는 영역(x: 10~370px, y: 0~553.93px) 밖에 위치해 100% 잘려서 전혀 보이지 않는 상태**였다.

이건 실제 제품에서 "일부 방명록 항목을 의도적으로 숨긴다"는 디자인 의도로 보기 어렵고(스크롤 가능한 피드에서 항목이 통째로 사라지는 건 버그에 가까움), 와이어프레임 캔버스를 정리하지 않은 채 export한 것으로 판단했다. 따라서:

- 절대좌표/회전 행렬을 그대로 재현하지 않고, 가이드 3번 규칙(절대좌표 → 문서 흐름)에 따라 **`columns-2` 기반 반응형 masonry 레이아웃**으로 전환했다.
- 잘려서 안 보이던 3개 카드를 포함해 **10개 카드 전부 문서 흐름에 포함**시켰다(콘텐츠 손실 방지가 화면 클리핑 버그를 그대로 재현하는 것보다 낫다고 판단).
- 각 카드의 살짝 기울어진 "압정" 느낌만 유지하기 위해 `matrix(...)`에서 회전각을 역산해 카드별로 `rotate-[Ndeg]` Tailwind 임의값 클래스를 하나씩 부여했다(예: `-rotate-[5deg]`). 정확한 좌표 재현은 포기했지만 시각적 성격은 남겨두는 절충안.
- 카드 순서는 원본 캔버스에서의 세로 위치(top 오프셋) 기준 오름차순으로 배치했다. `columns-2`는 좌→우가 아니라 "왼쪽 컬럼을 아래까지 채운 뒤 오른쪽 컬럼" 방식이라 원본의 2차원 산개 배치와 완전히 같지는 않지만, 반응형 모바일 화면에서 가장 단순하고 검증된 masonry 구현이라 채택했다(가이드 CLAUDE.md "Simplicity First").
- 카드 고정폭(110~180px, 760px 캔버스 기준으로 설계된 값)은 실제 360px 모바일 화면의 컬럼 폭과 맞지 않아 그대로 쓰지 않고 `w-full`(컬럼 폭에 맞춰 유동)로 전환했다.

## 3. 카드별 내부 순서 재배치 (column-reverse 정규화)

원본 카드 내부 컨테이너들이 대부분 `flex-direction: column-reverse`로 저작되어 있어(가이드 3번 규칙에서 언급된 Penpot 저작 트릭), DOM 순서와 실제 시각 순서가 반대였다. 각 카드 타입별로 `column-reverse`를 역산해 실제 시각 순서를 판단하고 정순(`flex-col`)으로 재배치했다:

- **PhotoCard**: 이미지(마지막 DOM 요소)가 위, 캡션(첫 DOM 요소)이 아래.
- **ColorCard**: 색상 스와치 3개(마지막 DOM)가 위, 라벨 텍스트(첫 DOM)가 아래.
- **PostcardCard**: 라벨("AI 엽서 · OOO", 마지막 DOM)이 위, 인용구(첫 DOM)가 아래. 이모지(🌅/💌)는 원본에서 `position: absolute`로 카드 우상단에 "우표"처럼 얹혀 있어 흐름에서 제외하고 그대로 절대배치 유지.
- **AudioCard**: 파형 바(마지막 DOM)가 위, 곡 제목(중간)이 가운데, 메타 텍스트("0:18 · AI 분석: ...", 첫 DOM)가 아래.
- **WeatherCard**: 이모지(마지막 DOM)가 위, 온도(중간)가 가운데, 장소·날씨 텍스트(첫 DOM)가 아래.
- **NoteCard**: 원형 뱃지 점이 `position: absolute`로 카드 좌상단에 얹혀 있고, 본문 텍스트만 흐름에 남아 재배치가 필요 없었음.

## 4. 디자인 토큰 대체 내역

대부분 색상은 `globals.css` 토큰과 정확히 일치했다(예: 색상 스와치 `#063e51`→`primary-900`, `#0a8ab5`→`primary-700`, `#c5edfa`→`primary-100`, `#45741f`→`tertiary-800`, `#cbe7b1`→`tertiary-200`, 파형 바 `#77be36`→`tertiary-600`, 오디오 카드 배경 `#2a2621`→`warm-neutral-900`, 엽서 카드 배경 `#f1f9e8`→`tertiary-50`, 노트 뱃지 `#77be36`→`tertiary-600`, `#076c8d`→`primary-800` 등). 정확히 일치하지 않아 대체한 항목만 정리:

| 원본 값 | 위치 | 대체 토큰 | 비고 |
|---|---|---|---|
| `#f59e0b` | "일몰의 오렌지빛" 색상 카드 스와치 2 | `sunny-yellow-500` (`#d5b615`) | 팔레트에 주황 계열이 없어 RGB 거리상 가장 근접한 sunny-yellow 톤 사용 |

## 6. 기타 임의 판단 사항

- **상태바(9:41, 신호/와이파이/배터리) 전부 제거**: 가이드 2번 규칙(항상 제거)에 따름.
- **정렬 드롭다운 chevron 아이콘**: 원본은 Penpot 특유의 절대좌표 기반 복잡한 path(뷰박스가 화면 전역 좌표계)를 사용했는데, 시각적으로 동일한 단순 셰브런(chevron-down) 화살표를 `viewBox="0 0 8 5"` 기준의 깔끔한 3점 path로 다시 그려 대체했다(원본 좌표 그대로 복사하면 가독성이 크게 떨어지고 재사용 가치도 없는 1회성 아이콘이라 판단).
- **PhotoCard 삽화 단순화**: 원본 사진 카드 중 하나("광치기 앞 카페, 당근케이크")는 손그림 스타일의 다각형 벡터 일러스트(커피/케이크 실루엣)를, 다른 하나("섭지코지, 바람 많던 날")는 실제 업로드 이미지 asset URL(pattern fill)을 사용하고 있었다. 둘 다 실제 에셋이 아니므로 가이드 5번 규칙에 따라 회색 정사각형 플레이스홀더(`bg-cool-neutral-200`)로 통일하고 `// TODO: 실제 이미지/에셋 교체` 주석을 남겼다.
- **필터 칩/카테고리 탭 활성 상태**: "전체"가 필터 칩과 카테고리 탭 양쪽에서 모두 활성(진한 배경/밑줄) 스타일로 되어 있어 그대로 `active: true` mock 값으로 반영했다.
- **카테고리 탭 밑줄 표현**: 원본 CSS는 활성 탭에 `border: 2px solid #222222`(4변 전체)를 지정해 두었으나, 이 컨테이너가 `overflow: hidden`인 43px 높이 안에 있고 일반적인 "언더라인 탭" 패턴이므로 `border-b-2`(하단 밑줄)로 해석해 구현했다.
- **클릭 가능 요소 버튼 승격**: 필터 칩, 카테고리 탭을 전부 `<button type="button">`으로 승격. `onClick` 로직은 미구현(정적 UI 단계).
- **목데이터**: 헤더 타이틀/부제, 필터/탭 라벨과 활성 상태, 정렬 라벨, 카드 10개(캡션/텍스트/색상/이모지/인용구/오디오 메타 등)를 전부 `mock` 객체 및 `cards` 배열로 추출.
- **"use client" 미부착**: 상태/이벤트 훅이 필요 없어 Server Component로 유지.
