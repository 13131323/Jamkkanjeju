# 지도 모달 조회 API 테스트 계획

- 상태: **완료**
- 실행일: 2026-10-26
- 전체 결과: 지도 모달 단위 48개·통합 15개와 기존 테스트 800개, 총 863개 통과. 최종 실행 실패·오류·건너뜀 0개.
- 대상 API: `GET /api/v2/map/modals`
- 기준 문서: `API_SPEC.md`, `BUISNESS_RULE.md`, `common/docs/commonError.md`

## 진행 방식

| 구분 | 방법 |
| --- | --- |
| 단위 테스트 | Spring·DB 없이 JUnit 5·AssertJ·Mockito로 요청 검증, 응답 변환, 서비스 분기를 검증한다. 공통 픽스처는 `map/support`에 둔다. |
| 통합 테스트 | `MySqlIntegrationTestSupport`를 상속하고 실제 MySQL 임시 DB·Flyway·MockMvc·실제 JWT로 검증한다. 외부 TourAPI만 Mock으로 격리하고 개발 자동 인증은 끈다. |

고정 날짜와 명시적으로 준비한 데이터로 검증한다. 테스트 준비 데이터는 트랜잭션 종료 시 롤백하고 JVM 종료 시 임시 DB와 접근 권한을 제거한다. 조회 API이므로 정상·오류·반복 요청의 DB 상태 보존을 확인한다.

1. 요청·응답 DTO와 서비스 단위 테스트를 구현하고 실행한다.
2. 임시 MySQL DB에서 통합 테스트를 구현하고 실행한다.
3. 기존 전체 테스트를 실행해 회귀 오류를 확인한다.
4. 임시 DB·권한 정리를 확인하고 결과를 기록한다.

## 완료 조건

- 계획한 단위·통합 테스트와 기존 전체 테스트가 통과한다.
- 두 유형의 응답·사용자별 격리·방명록 정렬과 제한·공통 및 도메인 오류가 검증된다.
- 외부 API·기존 개발 데이터·현재 시각에 의존하지 않는다.

## 발견하고 수정한 점

- 운영 코드 추가 수정 없이 새 테스트 63개와 기존 테스트 800개가 최종 전체 실행에서 통과했다.
- 요청 경계·보상 지급 여부 8가지 조합·참가 상태와 팀 상태·유형별 중복은 매개변수화 테스트로 검증했다. 잘못된 쿼리·인증 오류와 nullable 조합은 같은 준비 조건을 공유하는 테스트에서 여러 요청·값을 함께 검증했다.
- 단위 테스트 최초 컴파일에서 AssertJ와 픽스처의 `DATE` 정적 import 충돌을 발견해 필요한 AssertJ 메서드만 import하도록 수정했다.
- NaN·무한대는 기존 `@DecimalMin`·`@DecimalMax` 검증으로 거절됨을 확인했다. 별도 유한성 검증은 추가하지 않았다.
- ACTIVE 방명록 4건 중 방문일·ID 내림차순 최신 3건만 반환하며 전체 개수는 4로 유지됨을 실제 MySQL에서 검증했다. 다른 장소·길바닥·장소 참조 없음·INACTIVE 기록을 제외하고 작성자 없는 기록은 유지했다.
- 사용자별 방문·완료·보상 수령 여부와 다른 미션의 지급 이력이 섞이지 않음을 검증했다. 정상·반복·404·500 요청 전후 DB 스냅샷이 일치하고, 없는 보상 상태 행도 생성되지 않았다.
- 최초 전체 실행은 863개 중 기존 `ServerSpringApplicationTests.contextLoads` 1개가 MySQL `Too many connections`로 오류가 났다. 캐시된 테스트 컨텍스트의 연결 풀이 함께 유지되어 발생했으며, 실행 옵션 `spring.test.context.cache.maxSize=4`로 캐시 크기를 제한한 재실행에서 863개 모두 통과했다. 운영 코드·MySQL 전역 설정·공통 테스트 설정 파일은 변경하지 않았다.
- 별도 통합 실행, 최초 전체 실행, 전체 재실행에서 각각 생성한 `tour_test_dd2967c39a37483e90548ed8f6a756ad`, `tour_test_49f502b83195403aa078cc3b51762278`, `tour_test_08f80eb99b0041a6a4c95ca44c20f660`의 자동 삭제를 확인했다. 실행 종료 후 해당 DB와 접근 권한은 각각 0개이며 개발 DB·컨테이너·볼륨은 변경하지 않았다.

# 지도 장소 상세 조회 API 테스트 계획

- 상태: **완료**
- 실행일: 2026-10-26
- 전체 결과: 장소 상세 단위 51개·통합 14개와 기존 테스트 863개, 총 928개 통과. 실패·오류·건너뜀 0개.
- 대상 API: `GET /api/v2/map/locations/{locationId}`
- 기준 문서: `API_SPEC.md`, `BUISNESS_RULE.md`, `common/docs/commonError.md`

## 진행 방식

| 구분 | 방법 |
| --- | --- |
| 단위 테스트 | JUnit 5·AssertJ·Mockito로 요청·응답·추천·서비스를 격리한다. TourAPI 상세 이미지는 기존 클라이언트 테스트처럼 MockRestServiceServer로 외부 통신 없이 검증한다. |
| 통합 테스트 | MySqlIntegrationTestSupport·SpringBootTest·MockMvc·실제 JWT·임시 MySQL을 사용한다. 고정 Clock과 TourAPI Mock을 적용하고 테스트 준비 데이터는 롤백한다. |

지도 모달 계획·결과는 유지한다. 장소 상세의 날짜·좌표·후보·이미지 응답은 테스트가 직접 준비하고, 공통 보상·방명록 변환은 기존 모달 테스트를 재사용한다. 전체 회귀 실행은 앞서 확인한 연결 수 초과를 피하도록 실행 시 테스트 컨텍스트 캐시 크기를 제한한다. 개발 DB와 MySQL 전역 설정은 바꾸지 않는다.

- 새 테스트 65개를 추가했고 운영 코드 추가 수정 없이 기존 테스트를 포함한 928개가 최종 실행에서 모두 통과했다.
- 최초 단위 실행의 이미지 Mock이 보물찾기 장소 ID 한 개만 설정하여, 함께 선정된 협동 장소 ID 호출에서 Mockito 인자 불일치가 발생했다. 두 선정 대상에 맞춰 Mock 응답을 설정하고 엄격한 검증은 유지했다. 수정 후 단위 51개가 모두 통과했다.
- 좌표·페이지 입력과 후보 부족·참가/팀 상태·외부 오류는 매개변수화 테스트로 묶었다. 방명록의 페이지 경계·정렬·크기 변경과 인증·잘못된 요청은 같은 준비 데이터를 사용하는 테스트 안에서 여러 요청으로 확인했다.
- 보상·방명록의 공통 변환 분기는 기존 지도 모달 테스트로 회귀 검증하고, 상세 응답에서는 설명·추천 장소·이미지·페이지 연결을 추가로 검증했다.
- 상세 이미지가 숫자 순번·동일 순번·해석 불가 순번 순서대로 정렬되고 중복 제거 후 최대 다섯 장으로 제한됨을 외부 연결 없이 확인했다. 빈 URL과 숫자 URL은 제외하고 유효한 URL 문자열은 그대로 유지했다.
- 실제 MySQL에서 방명록 21건은 기본 첫 페이지 20건·다음 페이지 1건, 정확히 20건은 다음 페이지 없음, 범위 밖 페이지는 빈 목록임을 확인했다. 사용자 size 변경과 페이지 간 중복 없음, 작성자 없는 ACTIVE 기록 유지·제외 대상 필터도 검증했다.
- 추천은 두 유형 합계 거리순 세 건이며 완료·비활성·장소 없음은 제외했다. 다른 사용자와 PENDING 참가 이력은 해당 사용자의 완료로 잘못 처리되지 않았고, 현재 장소의 완료 미션은 상세에 유지했다.
- 정상·반복·404·500 요청 전후 DB 스냅샷이 일치했다. 조회 중 방문·지급 상태·보유 보상·진행도 데이터를 생성하거나 수정하지 않았다.
- 전체 회귀 실행에는 기존 연결 수 초과 재발을 피하기 위해 실행 옵션 `spring.test.context.cache.maxSize=4`를 사용했다. MySQL 전역 설정이나 공통 테스트 설정 파일은 바꾸지 않았다.
- 별도 통합 실행의 `tour_test_ffa42662b7a74f6195c2a71fb5bc2b41`과 전체 실행의 `tour_test_f15826c3ce9e4de094fee68fd28b37f6`이 자동 삭제되었고, 해당 DB와 접근 권한이 각각 0개임을 확인했다. 개발 DB·컨테이너·볼륨은 변경하지 않았다.
