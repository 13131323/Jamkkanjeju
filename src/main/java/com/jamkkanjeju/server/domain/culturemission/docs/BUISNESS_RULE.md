# 문화 미션 시작/이어하기 비즈니스 규칙

## 1. 요청 및 현재 사용자 확인

- 요청 형식과 오류 응답은 [API 명세](./API_SPEC.md)를 따른다.
- 현재 사용자 ID는 검증된 인증 정보에서 가져온다.
- 요청에서 사용자 ID를 받지 않는다.
- 인증 정보의 사용자 ID에 해당하는 사용자를 조회한다.
- 사용자가 존재하지 않으면 `UNAUTHORIZED`로 처리한다.

## 2. 문화 미션 확인

- 요청의 `missionId`로 `CULTURE_MISSION.mission_id`에 해당하는 문화 미션을 조회한다.
- 문화 미션 ID는 공통 `MISSION.id`와 동일하다.
- 해당 문화 미션이 존재하지 않으면 `CULTURE_MISSION_NOT_FOUND`로 처리한다.
- 문화 미션의 상태가 `INACTIVE`이면 `CULTURE_MISSION_INACTIVE`로 처리한다.
- 비활성 여부는 최초 시작, 이어하기, 완료 후 재시작 모두에 동일하게 적용한다.
- 문화 미션의 존재 여부와 활성 상태를 확인하기 전에는 진행도를 생성하거나 초기화하지 않는다.

## 3. 현재 진행도 조회

- 현재 사용자 ID와 문화 미션 ID를 함께 사용해 `CULTURE_MISSION_PROGRESS`를 조회한다.
- 같은 사용자와 같은 문화 미션의 진행도는 상태에 관계없이 최대 한 건만 유지한다.
- 진행도가 없으면 최초 시작, `IN_PROGRESS`이면 이어하기, `COMPLETED`이면 재시작으로 판단한다.
- 다른 사용자의 진행도는 조회하거나 변경하지 않는다.

## 4. 진행 상태에 따른 처리

### 4.1 최초 시작

- 현재 사용자와 문화 미션에 해당하는 진행도가 없으면 새 진행도를 생성한다.
- `culture_mission_id`에는 요청한 문화 미션 ID를 설정한다.
- `user_id`에는 현재 사용자 ID를 설정한다.
- `mission_status`는 `IN_PROGRESS`로 설정한다.
- `current_quiz_index`는 1로 설정한다.
- `correct_count`는 0으로 설정한다.
- `last_completed_at`은 `null`로 설정한다.
- 새로 생성한 진행도를 반환 대상으로 사용한다.

### 4.2 이어하기

- 기존 진행도가 `IN_PROGRESS`이면 해당 진행도를 그대로 사용한다.
- 진행도를 추가로 생성하거나 기존 진행도를 초기화하지 않는다.
- 진행도 ID, 현재 퀴즈 번호, 정답 개수와 마지막 완료 시각을 유지한다.

### 4.3 완료 후 재시작

- 기존 진행도가 `COMPLETED`이면 같은 진행도를 초기화해 재사용한다.
- 새 진행도를 생성하거나 기존 진행도를 삭제하지 않는다.
- 기존 진행도 ID를 유지한다.
- `mission_status`는 `IN_PROGRESS`로 변경한다.
- `current_quiz_index`는 1로 초기화한다.
- `correct_count`는 0으로 초기화한다.
- `last_completed_at`은 마지막으로 완료한 시각이므로 재시작 시 지우지 않고 유지한다.
- 보상 지급 이력은 별도 `CULTURE_MISSION_REWARD_STATUS`에서 관리하므로 진행도 재시작 시 초기화하거나 삭제하지 않는다.

## 5. 퀴즈 조회 및 응답 구성

- 해당 문화 미션에 연결된 `CULTURE_MISSION_QUIZ`를 조회한다.
- 퀴즈는 `quiz_index` 오름차순으로 정렬한다.
- `quizCount`는 해당 문화 미션의 전체 퀴즈 개수로 구성한다.
- `cultureMissionProgressId`는 생성하거나 재사용한 진행도의 ID로 구성한다.
- `currentQuizNumber`는 진행도의 `current_quiz_index`를 사용한다.
- `current_quiz_index`는 사용자가 다음에 풀 퀴즈 번호를 의미한다.
- 최초 시작과 재시작의 현재 퀴즈 번호는 1이며, 이어하기는 저장된 번호를 그대로 사용한다.
- `quizDetails`에는 정렬된 전체 문제의 이미지, 질문, 선택지, 정답, 힌트와 해설을 포함한다.
- 객관식과 주관식 모두 저장된 정답 문자열을 사용한다.
- 이미지, 선택지, 힌트와 해설이 없으면 해당 값을 `null`로 유지한다.
- 최초 생성과 기존 진행도 재사용 여부에 따른 정상 응답 구분은 [API 명세](./API_SPEC.md)를 따른다.

## 6. 재요청 및 진행도 유지

- 최초 시작 이후 같은 요청을 다시 처리하면 생성된 `IN_PROGRESS` 진행도를 이어서 반환한다.
- 재시작 직후 같은 요청을 다시 처리해도 이미 `IN_PROGRESS`인 진행도를 다시 초기화하지 않는다.
- 반복 요청으로 같은 사용자와 문화 미션에 진행도가 중복 생성되지 않아야 한다.
- 이 API는 퀴즈 풀이 결과를 제출하는 요청이 아니므로 현재 퀴즈 번호와 정답 개수를 증가시키지 않는다.
- 이 API에서는 미션을 완료 처리하거나 보상을 지급하지 않는다.

## 7. 트랜잭션 범위

- 현재 사용자와 문화 미션 확인, 진행도 조회, 최초 생성 또는 재시작 초기화, 응답에 필요한 퀴즈 조회를 하나의 트랜잭션으로 처리한다.
- 진행도 생성이나 초기화 이후 처리에 실패하면 해당 변경을 롤백한다.
- 재시작 요청이 실패하면 기존 완료 상태, 퀴즈 번호, 정답 개수와 마지막 완료 시각이 유지되어야 한다.
- 모든 처리가 성공한 경우에만 정상 응답을 반환한다.
