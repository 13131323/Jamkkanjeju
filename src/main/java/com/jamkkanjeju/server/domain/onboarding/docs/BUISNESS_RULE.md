# 사용자 온보딩 완료 비즈니스 규칙

## 1. 요청 구분 및 입력값 검증

- 요청 Body에 온보딩 선택 필드가 하나도 없으면 **나중에 할게요**를 선택한 요청으로 판단한다.
- **나중에 할게요** 요청은 빈 객체만 허용한다.
- 일반 온보딩 완료 요청은 `expectations`, `transportation`, `travelStyle`을 모두 포함해야 한다.
- `expectations`는 한 개 이상의 값을 포함해야 한다.
- `expectations`에 같은 값을 중복해서 전달할 수 없다.
- 각 선택값은 해당 enum에 정의된 값만 허용한다.
- 일부 필드만 전달하거나 검증 조건을 만족하지 못한 요청은 `INVALID_REQUEST`로 처리한다.

## 2. 현재 사용자 확인

- 현재 사용자 ID는 검증된 액세스 토큰의 인증 정보에서 가져온다.
- 요청에서 사용자 ID를 받지 않는다.
- 인증 정보의 사용자 ID에 해당하는 사용자를 조회한다.
- 해당 사용자가 존재하지 않으면 인증 정보 없음으로 처리한다.

## 3. 온보딩 선택값 변경

- 일반 온보딩 완료 요청이면 요청에 포함된 여행 기대 항목을 사용자의 최종 선택값으로 저장한다.
- 기존 여행 기대 항목이 있으면 모두 제거한 뒤 새 요청값으로 교체한다.
- 주 이동 수단은 사용자당 하나만 유지하며 새 요청값으로 변경한다.
- 자투리 시간 여행 방식은 사용자당 하나만 유지하며 새 요청값으로 변경한다.
- 요청의 enum 값에 대응하는 기준 데이터가 모두 존재하는지 확인한 뒤 사용자 선택값을 변경한다.
- **나중에 할게요** 요청이면 기존 여행 기대 항목, 주 이동 수단, 자투리 시간 여행 방식을 모두 제거한다.

## 4. 온보딩 결과 배정

- 일반 온보딩 완료 요청에는 온보딩 결과를 하나 배정한다.
- 온보딩 선택값과 결과의 최종 매칭 기준이 확정되기 전까지 `여행자`를 제외한 온보딩 결과 중 하나를 무작위로 배정한다.
- TODO: 온보딩 결과 매칭 기준이 확정되면, 일반 온보딩 완료 요청에 대해 선택값과 매칭 기준에 따라 최종 온보딩 결과를 배정하도록 변경한다.
- **나중에 할게요** 요청에는 `userType`이 `여행자`인 기본 온보딩 결과를 배정한다.
- 기존에 배정된 온보딩 결과가 있으면 새로 결정한 결과로 교체한다.
- 온보딩 결과가 배정되면 해당 사용자는 온보딩을 완료한 것으로 판단한다.
- 배정 가능한 온보딩 결과가 없거나 기본 온보딩 결과가 없으면 처리를 실패시킨다.
- 이 API에서는 AR 캐릭터를 배정하거나 변경하지 않는다.

## 5. 응답 데이터 구성

- 응답의 사용자 ID는 인증된 현재 사용자의 ID를 사용한다.
- `onboardingCompleted`는 온보딩 결과가 배정되어 있으면 true, 없으면 false로 계산한다.
- `onboardingResult`는 최종적으로 사용자에게 배정된 온보딩 결과를 사용한다.
- **나중에 할게요** 요청도 기본 온보딩 결과가 배정되므로 정상 응답의 `onboardingCompleted`는 true다.

## 6. 재요청 처리

- 이미 온보딩을 완료한 사용자도 다시 요청할 수 있다.
- 재요청은 기존 선택값과 온보딩 결과를 새 요청 결과로 교체한다.
- 동일한 요청을 여러 번 처리해도 사용자별 여행 기대 항목이 중복 저장되지 않아야 한다.
- 재요청이 실패하면 기존 온보딩 정보는 유지되어야 한다.

## 7. 트랜잭션 범위

- 사용자 조회 이후 선택값 변경, 온보딩 결과 배정까지 하나의 트랜잭션으로 처리한다.
- 선택값 또는 온보딩 결과 중 하나라도 변경에 실패하면 전체 변경을 롤백한다.
- 모든 변경이 성공한 경우에만 정상 응답을 반환한다.
