# 협동 미션 시작/이어하기 API 테스트 계획

- 상태: **실행 완료**
- 실행일: 2026-10-19
- 결과: **협동 미션 32개 전부 통과, 기존 테스트 포함 전체 513개 전부 통과** (실패·오류·건너뜀 0개)

## 진행 방식

| 구분 | 방법 |
| --- | --- |
| 단위 테스트 | Spring과 DB 없이 JUnit 5, AssertJ, Mockito로 응답 구성, 검증 순서, 서비스 분기와 저장 호출을 검증한다. 시각은 `Clock.fixed`로 고정하고 난수는 특정 값 대신 형식·길이를 검증한다. |

개발용 자동 로그인은 끈다. 개발 DB와 볼륨은 변경하지 않고, 테스트 종료 시 임시 DB와 접근 권한이 제거되는지 확인한다.

## 발견하고 수정한 점

- 응답에 `teamToken`을 추가했다. 신규 시작과 기존 `HOST + ACCEPTED` 이어하기는 저장된 토큰을 반환하고, `HOST + PENDING`, `MEMBER + ACCEPTED`, `MEMBER + PENDING`은 `null`을 반환한다.
- Swagger 테스트는 개별 API에 `security`가 있는 것으로 잘못 가정했던 부분을 수정해 기존 OpenAPI 전역 `bearerAuth` 설정을 확인한다.
- 전체 회귀 실행에서 캐시된 테스트 컨텍스트의 연결 풀이 누적되어 MySQL `Too many connections`가 발생했다. 새 협동 미션 통합 테스트 기반에 `@DirtiesContext(AFTER_CLASS)`를 적용해 각 클래스 종료 후 컨텍스트·연결 풀을 닫도록 수정했다. 서버 연결 제한이나 기존 테스트·운영 설정은 변경하지 않았다.
- 상태·역할 조합은 매개변수 테스트로, 없는 미션·다른 유형 ID와 미인증·없는 사용자 토큰은 각각 한 테스트 안에서 함께 검증했다. 계획에서 제외한 정책이나 추가한 정책은 없다.
- 참가자 저장 실패는 실제 참가자를 저장·flush한 뒤 예외를 발생시켰으며, 테스트 트랜잭션 없이 호출해 팀·참가자 전체 롤백과 기존 데이터 보존을 확인했다. 이후 정상 재요청으로 잠금 해제도 확인했다.
- 같은 사용자·같은 미션의 독립 요청 4개에서 201 한 건·200 세 건, 동일 진행도 ID, 팀·본인 참가자 각 한 건을 확인했다. 서로 다른 미션 또는 사용자 요청은 각각 새 팀을 생성했다.
- Java 21에서 단위 테스트 → 통합 테스트 → 전체 회귀 테스트 순서로 다시 실행했다. 최종 전체 실행은 2026-10-19 15:07:23(KST)에 성공했다.
- 종료 후 MySQL을 조회해 `tour_test_<UUID>` 임시 DB 0개·해당 접근 권한 0개를 확인했다. 개발 DB·볼륨은 변경하지 않았다.

# 협동 미션 참여 요청 수락/거절 API 테스트 계획

- 대상 API: `PATCH /api/v2/cooperative-missions/{cooperativeMissionProgressId}/participants/{participantId}`

| --- | --- |
